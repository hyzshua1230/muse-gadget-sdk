# Spec：EasyInput V2.0 适配 Muse Gadget SDK

## 1. 状态与目标

- 日期：2026-10-10。
- 状态：首期范围、核心键位和阶段划分已确认；技术评审修订完成，开发和真机验收尚未执行。
- 文档版本：0.2。
- 代码基线：`main`，提交 `812c46f9fe42b69d916613a9dc702cbac5ff7b54`。
- 硬件：EasyInput V2.0；固件别名 `v2`；PCB 丝印 AI Keyboard V2.1。三者指向同一套硬件基线。
- 工具环境：已安装并验证 ESP-IDF 6.0.1，工具位于 D 盘；旧版 5.5.5 保留。

目标是在复用上游配网、连接及语音会话逻辑的基础上，把本板实现为“8 键、旋钮、灯光反馈与语音交互的桌面控制器”。本规格定义拟实现的行为、技术约束、开发边界和验收标准，作为后续开发依据。

资源利用以交互完整、运行稳定、功耗可控为标准。CPU、PSRAM、Flash 的使用率本身不作为成功指标。

硬件事实、已确认需求和待确认参数在本文中分别标识。用户已在 2026-10-10 的评审中确认首期范围、第 8 节核心键位，以及睡眠/唤醒放到第二阶段。扩展服务、硬件运行参数和静音持久化策略仍需按对应任务明确；当前任务不包含开发或真机执行。

## 3. 已确认的硬件合同

| 资源 | 事实 | 适配约束 |
| --- | --- | --- |
| SoC | ESP32-S3R8 | 目标为 `esp32s3` |
| PSRAM | 8 MB、Octal、3.3 V | 不能继承默认 Quad 配置；实际容量需启动验证 |
| Flash | W25Q128 系列、16 MB | 配置容量与分区总边界须匹配；速率、模式需核验 |
| S1～S8 | GPIO2/47/38/41/1/6/7/48，低有效 | 独立输入，允许组合键；动作由项目决定 |
| 编码器 | A=17、B=16、按压=18 | A/B 为正交相位；方向及每格计数需实测 |
| WS2812 | GPIO12，5 颗，GRB | 必须按 5 像素发帧 |
| 独立绿灯 | GPIO42，高有效/PWM | 可承担连接或静音提示；语义待评审 |
| 共享外设电源 | GPIO8，高有效，供 LED/MIC/SPK | 任何消费者不能擅自断开其他消费者的电源 |
| 麦克风 | BCLK/WS/DIN=9/10/11 | 时钟、位宽、slot、采样率需与器件匹配 |
| 扬声器 | BCLK/WS/DOUT=14/13/15，MAX98357A 路径 | 音量需由适配层实现，不可沿用 AIC3204 寄存器控制 |
| 电池电压 | SEN_EN=5；ADC=4，约 VBAT/2 | 校准后估算端电压，不代表精确剩余容量 |
| 外部供电 | GPIO40，低表示存在 | 只有外部供电存在时才解释充电信号 |
| 充电状态 | GPIO39；外部供电时高=充电中、低=充满 | 不能反转逻辑 |
| KEY_WAKE | GPIO21，低有效汇总 | 唤醒后重扫输入；不能直接识别来源 |
| USB | D-/D+=19/20 | HID 与调试入口需一起规划 |
| UART0 | RX=44、TX=43；J4 接口 | 外部串口按信号方向交叉连接 |
| BOOT | GPIO0 对应专用下载电路 | 不作为配对键或产品键；本板开机短按即可进下载模式 |

GPIO26～37 按板级合同保留给存储相关总线。其他空闲脚也不能未经原理图检查直接复用。

GPIO8 的冷启动顺序：先锁存关闭共享电源，将下游命令输出设置为安全状态，GPIO11 保持浮空输入，再开启共享电源并确认稳定，随后初始化 I2S 和灯条。关断前先停止所有共享消费者并恢复安全引脚状态。稳定等待时间尚无统一已验证数值，不能把另一块板的延时当作本板规格。

共享电源必须由单一板级模块拥有，灯光与音频模块不得直接切换 GPIO8。当前 `app.c` 先调用 `led_status_init()`，之后才调用 `voice_init()`，因此本板安全上电准备必须发生在灯光初始化前，不能只放在语音驱动初始化中。首期初始化成功后允许共享电源保持开启；播放停止通过停止数据输出或数字静音完成，不关闭仍被灯光使用的电源。

首期采集和播放采用交替使用：启动录音前停止当前播放；静音或取消录音时停止采集。并发录放、回声消除和持续监听属于后续能力，不能把“两套 I2S 引脚”视为已验证的全双工效果。

历史会话曾依据原理图快照核对麦克风型号及右声道选择。实现时仍需把当前装配、slot 和有效数据位的验证结果记录下来，避免把历史定制固件的行为当作当前上游基线。

## 5. 技术方案与决策依据

### 拟采用：复用无屏语音路径，新增 EasyInput 板级适配

复用 Link 配网、Noise 连接、`voice.c`、无屏语音会话及播放逻辑；增加独立本板配置、音频驱动、多键输入、灯光和电源适配。

优势是与现有硬件交互方式一致，改动集中在边界。代价是现有单键和灯效配置需扩展，电池健康数据不能直接沿用 UI 分支。

### 备选方案评估：Muse 全屏 UI 路径

可以利用更多 UI 板的电池、设置及板接口，但要处理显示、LVGL 和页面逻辑依赖。当前草案不采用此路径；若无屏方案出现无法满足需求的限制，先修订规格再改变架构。

### 备选方案评估：仅修改 DevKit 引脚

仅适合非常有限的单键单灯验证，无法解决音频硬件差异、多键、共享电源及存储问题，不作为完整适配方案。

首期以无屏方案为开发基线。`components/muse/CMakeLists.txt` 已有 `HOMEHUB_VOICE` 的独立构建分支，可以复用语音会话并保持 `MUSE_ENABLED` 关闭。驱动级参数通过第 6 节验证确定；发生接口或范围变化时先更新规格，不能静默更换实现路径。

### 必须新增或扩展的接口语义

- 多键模块向语音模块发送开始、结束、取消和静音变化事件。现有 `voice.c` 只有 PRESS/RELEASE 内部事件，`voice.h` 没有独立取消接口；本板适配必须补齐，不能把 S4 伪装成再次按下 S1。
- S4 取消录音时丢弃当前尚未提交的录音，不把取消转换成松开提交；等待回复或播放时取消会话并停止播放，不自动开始新录音。
- S2 在录音过程中开启软件静音时，立即停止采集并取消当前尚未提交的录音；再次解除静音不自动录音，必须重新按 S1。已提交到服务端的内容不能靠本地静音撤回。
- `voice_board_muted()` 提供软件静音状态和音频不可用状态。不能通过关闭 GPIO8 实现只静音麦克风；也不能只在录音开始时检查静音状态。
- 按键任务只投递事件，音频任务处理 I2S 和取消操作；不在按键回调中阻塞等待网络结果。
- 扬声器数字音量采用饱和转换，音量 0 输出静音；音量范围、旋钮步进和延后保存先沿用上游的 0～100、每格 5、停止旋转 2 秒后保存。静音标志是否跨重启保存仍为待确认产品项。
- 首期通过现有 `device.health` 接入本板的电池电压、外部供电和充电状态。无法测量时返回未知/null；没有校准依据时不提供看似精确的电量百分比。不能为读取这些数据而启用全屏 UI。

验证伴随各开发任务执行，并按用户授权进行编译、烧录和真机操作。新代码必须按本仓库适用的 AGENTS.md 检查；新增依赖和第三方脚本按用户规则确认。以下是计划，所有结果当前均为“未验证”。

| S12 | 16 MB 分区是否合理？ | 检查分区边界、不重叠、bootloader/表偏移及 SDK 产品分区；核对实际固件占用 | 分区表、应用大小、两槽余量及产品分区使用情况 | 总边界不超过 16 MB；两应用槽均能容纳首期固件，空余比例低于 10% 时必须重新评审 |

若缺少示波器或电流测量设备，S02/S11 的相应测量项标记为“未验证”，软件日志不能替代电气或功耗结论。D19/D20 是否装配、编码器是否参与汇总唤醒，也不得仅凭 KEY_WAKE 名称判断。

S10 的 ADC 误差阈值须在电池校准前确认；回复等待超时和网络失败的反馈时限须在 D4 前冻结。S03/S04 的数据位、采样率和供电稳定条件在 D1/D2 中确定。上述待定值不能作为已经通过的验收项。

## 7. 内存、存储及实时性要求

### 分配与实现要求

- 优先把较大音频和网络缓冲放到 PSRAM。
- 保留内部 RAM 给 DMA、实时驱动、关键任务及无线栈；具体分配能力按所选驱动核实。
- 16 kHz、PCM16 单声道的 15 秒录音数据为 480,000 字节，约 469 KiB。这只是不含协议、任务与其他缓冲的原始音频容量。
- 当前播放器的 10 秒、16 kHz PCM16 缓冲为 320,000 字节，约 313 KiB。
- 上游还分配语音会话队列、MP3 缓冲、TLS、BLE 和隧道资源。不能用前两项相加推断整体占用。
- 首轮保留上游语音采集与播放对外格式；若变更格式，须评估重采样和播放路径的共同影响。
- 首轮通过任务阻塞、队列及缓冲保证实时性；绑核或提高优先级须由丢帧、延迟和负载证据驱动。

## 9. 扩展能力的独立准入条件

### TTS

- 先用已知音频证明播放正确，再接入真实文字回复。
- 评审 TTS 提供方式、返回格式、网络延迟、取消行为及服务不可用时的用户反馈。
- 按 `start_tts()` 和已有解码流程接入，保留流量控制与打断能力。
- 没有 TTS 时，基线验收只要求 Muse App 中能收到文字回复；不能把“没有朗读”误判为扬声器失败。

### USB HID

- 增加 TinyUSB/HID 能力前评审依赖及设备身份。
- ESP32-S3 的 USB-OTG 与 USB Serial/JTAG 共用内部 PHY。当前 USB 接口采用 HID 后，调试入口须一并设计：评估 HID+CDC 复合设备或板上 UART；不能假设原生 Serial/JTAG 仍同时可用。
- 不为解决 USB 冲突写入 eFuse。
- 输入法、Unicode 文本输入和电脑端兼容性另行验证；HID 按键能力不等于直接发送任意中文字符串。

### ESP-SR

- 先评估单麦克风的音频前端、唤醒词和少量固定命令。
- 记录具体模型及其 CPU、内部 RAM、PSRAM、Flash 占用；官方参考板 benchmark 不代表本板成绩。
- 持续监听需要保持麦克风供电，应与电池待机目标一起决策。
- 软件 AEC 需要播放参考与时序匹配，不能继承 XMOS 板的现成回声消除结论。
