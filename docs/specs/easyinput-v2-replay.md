# EasyInput V2：S3 继续播放与重播上一条回复

## 状态与目标

状态：暂停/继续调整版已实现、编译和烧录，新固件启动已确认；实机功能验收等待恢复Wi-Fi并操作按键。历史执行记录保留。日期：2026-10-10。

用户确认：在 S1 提问后的首次朗读中途按 S4，希望 S3 能从中断位置继续；整条播放完成后再次 S3 则从头重播。S4 在已经开始朗读时定义为暂停，保留本轮音频和已播放位置。继续播放/重播不重新识别、不再次向 Muse 提问、不重新调用 Qwen TTS。

适用范围：EasyInput V2 当前 Qwen ASR / Qwen TTS 固件。其他板型保持现有行为。

## 当前代码依据

- `esp32/main/button.c`：第一版已将 S3 接入重播请求；S1 说话、S2 静音、S4 取消、S8 配对/恢复。
- `esp32/main/voice.c`：同一语音任务负责录音、等待回复和播放，支持取消与新一次 S1 录音中断播放。
- `esp32/main/voice_player.h`：播放器输入为 16 kHz、单声道 PCM16；复用当前音量与扬声器输出路径。
- `esp32/components/muse/muse_chat_session.cpp`：Qwen 返回 24 kHz、单声道 PCM16，重采样后送入播放器。第一版在首次播放成功后发布缓存；首次播放取消会清除缓存，正是本次反馈的触发条件。
- 播放器具有最多 10 秒预读缓冲，必须以实际输出进度定位暂停点，不能使用写入队列或会话读取的位置作为已播放位置。
- 当前 TTS 有 4 MiB PCM 上限，设备具有 8 MiB PSRAM。重播不能简单额外复制一个同等大小的音频缓冲区。

## 操作规则（拟定）

| 场景 / 操作 | 预期行为 |
|---|---|
| 已暂停且完整音频准备就绪，短按 S3 | 从保存的位置继续播放 |
| 整条回复已播放完成，短按 S3 | 从头重播最近一轮回复 |
| 首次播放、继续播放或重播中再次按 S3 | 忽略，不重启、不排队 |
| 录音、识别、等待回复时按 S3 | 忽略，不排队 |
| 首次朗读已暂停、音频尚未完整准备时按 S3 | 保存一次续播请求，缓存完整就绪后自动从暂停点继续；重复S3不叠加请求 |
| 首次播放、继续播放或重播中按 S4 | 暂停声音，记录位置并保留本轮音频；反复按 S4 不清除或重置位置 |
| 录音、识别或等待回复且尚未开始朗读时按 S4 | 保持原取消行为，不承诺存在可继续播放的音频 |
| 暂停、继续播放或重播时按住 S1 | 放弃本轮并开始新录音，等待旧播放退出后再采音 |
| 任一播放过程中旋转旋钮 | 实时使用当前音量；延续现有音量保存规则 |
| 静音时按 S3 | 不播放，不排队，保留当前静音灯光 |
| 播放期间按 S2 开启静音 | 暂停声音，保留音频与位置；取消静音不自动续播，需按 S3 |
| 完整缓存有效但网络断开 | 可本地继续/重播；独立联网灯仍反映实际连接状态 |
| 无缓存时按 S3 | 使用现有柔和的 3 灯红色播放错误提示 6 秒，记录 `NO REPLAY AUDIO`，不调用云端 |
| 重播写入或扬声器输出失败 | 停止播放，显示播放错误并记录原因；不自动重试 |

S3 按下一次只触发一次，沿用当前按键消抖。长按不增加第二种业务功能。

首次朗读暂停后，如果本轮还有已发起但未完成的回复/合成，声音立即停止，已有任务继续完成本轮缓存；不追加提问或自动重新合成。S3 此时保存一次续播请求，完整缓存就绪后自动续播。新提问、强制取消或失败清除这个请求；静音时不自动播放。如果后续合成失败，不能把半条音频当成完整回复，按原错误规则报告并清除本轮缓存。

## 缓存生命周期与内存边界（拟定）

1. 只保存最近一轮回复，不写 Flash、NVS 或文件，不保存用户录音；重启和恢复设置后为空。
2. S1 被接受为新录音请求时，先清除旧缓存和暂停点，避免旧音频与下一轮 ASR/TTS 大缓冲区同时占用 PSRAM。新录音被取消、识别失败或合成失败时，缓存保持为空；播放期间 S4 暂停不属于此清除条件。
3. 新回复音频完整生成后即具备保存资格，不要求首次播放结束。不得将未完成的半条音频标为完整缓存。多条消息属于同一轮时，按首次朗读顺序组成缓存；首次播放中途暂停也要保留这次回复。
4. 缓存存放于 PSRAM，音频数据总量不超过 4 MiB，约131秒。将已输出的Qwen 24kHz PCM原地转为与首次播放相同的16kHz PCM并收缩缓冲；重播直接复制到播放器，不同时保留完整24kHz与16kHz两份副本。
5. 多消息缓存与分块合成必须核对累计容量及临时缓冲峰值；超过容量或分配失败时明确记录 `REPLAY CACHE TOO LARGE` / `REPLAY CACHE NO MEMORY`，本轮不发布缓存。缓存问题不得改变正常首次朗读的成功/失败结果。
6. 播放、缓存发布和释放由明确的任务所有者串行处理；按键任务仅提交请求，避免播放过程中释放音频、重复释放或旧请求误播放新缓存。
7. 暂停点依据播放器实际成功输出的样本计算，并核对 I2S/DMA 尚未播出的尾部；不能依据已经预读进 10 秒缓冲区的样本数。暂停/继续不得跳过未听到的整段音频。播放完成后将状态记为已结束，下次 S3 重置到开头。
8. 暂停点必须覆盖首次朗读及后续重播，包含消息边界和重采样状态；不使用百分比、文字长度或估算语速定位。

“上一条”指最近一轮完整生成、且之后尚未开始新录音的回复，无需首先听完。新一轮失败后仍不保留更早回复，沿用既有单轮缓存和峰值内存约束。

## 灯光与反馈

- 首次朗读、继续播放和重播使用当前柔和的绿色播放动画，暂停或结束后回到现有空闲/静音状态。第一阶段不增加新的暂停灯色。
- 音量调节、静音与播放错误沿用当前灯光优先级，不提高亮度。
- 不为本功能调用 TTS 生成提示语，不增加提示音资源。
- 日志记录暂停点、继续播放起点、从头重播、样本数/时长、结束及失败原因，不新增回复正文、密钥或云端音频 URL 输出。

## 验收标准

| 验证场景 | 通过条件 |
|---|---|
| 开机后无历史按 S3 | 无声音、播放错误提示正确；设备仍可正常录音 |
| 短句回复完成后按 S3 两次 | 两次均从头重播同一完整内容，日志无新增 ASR/Muse/TTS 请求 |
| 首次朗读中途 S4，再按 S3 | 在 500 ms 内暂停；完整音频就绪后从中断位置继续，不从头重播、不跳过后续内容 |
| 重播/继续播放中途 S4，再按 S3 | 保存本次实际位置并继续；重复暂停/继续至少 3 次，内容连续 |
| 重播期间 S1 | 无旧音频与采音重叠，新录音及新回复正常；新回复替换旧内容 |
| 首次朗读暂停时合成尚未结束 | 立即静音，继续完成本轮缓存；S3保存续播请求，完整就绪后自动继续 |
| TTS 失败 / 音频不完整 | 不发布残缺缓存，明确报错，不重新请求云端补齐 |
| 完整播放结束后再次 S3 | 从头播放；结束状态不被当作暂停状态 |
| 任务忙碌时多次 S3 | 不打断当前任务，任务结束后不自动重播 |
| 静音、取消静音、旋钮 | 静音无声、不自动续播；S3 从静音前位置继续，旋钮可实时调音量 |
| 断网后继续/重播 | 完整缓存无需云端即可播放，联网灯不误亮 |
| 长回复 / 多消息回复 | 内容顺序与首次朗读一致，无越界、截断缓存、重复释放 |
| 连续 10 轮新回复与重播 | 无重启、内存持续流失或播放失败，记录 PSRAM 最小空闲及最大连续块 |
| 重启 / 恢复设置 | 缓存清空；既有配对、按键与音量行为无回归 |
