| 决策 | 结果 | Spec 落点 |

## 2. 发现的问题与修订结果

P1 表示会导致实现范围、行为或阶段验收不确定，需要修正规格；P2 表示对应功能开始前需要补齐的参数或验收细节。这里的“已修订”只表示文档处理完成，不表示固件能力已实现。

### F01 · P1：首期范围和键位没有冻结

0.1 的 R07 把电池检测、睡眠和唤醒放在同一首期需求中；§8 的按键动作均为候选。S3 重播又依赖尚不属于首期的 TTS 能力，S5～S7 宏操作也没有对应的首期协议实现。

影响：开发者无法确定首期交付边界，可能提前引入 HID/TTS 或把恢复功能放到语音键上。

处理：用户已确认范围、核心键位及功耗阶段。0.2 把睡眠/唤醒移到第二阶段，S3/S5～S7 与旋钮按压首期只验输入，配对/恢复独立放到 S8。

状态：范围问题已修订；静音持久化和灯光语义仍待决定，见 §3。

### F02 · P1：取消与录音中静音没有接口和状态语义

源码依据：

- [voice.c](../../esp32/main/voice.c) 的内部事件只有 PRESS/RELEASE；`on_press()` 在开始时检查静音。
- [voice.h](../../esp32/main/voice.h) 没有独立取消或静音变化入口。
- `reply()` 在收到再次按下时取消当前轮次并返回“开始新轮次”，这不等于 S4 的独立取消行为。
- [button.c](../../esp32/main/button.c) 中未被语音认领的按住事件仍可进入长按恢复逻辑。

影响：如果直接转接按键，S4 可能变成重新录音，录音中静音可能仍采集，断网或静音时长按 S1 可能进入恢复逻辑。

处理：0.2 明确取消、静音变化、按键路由与音频任务责任。取消不提交当前未提交录音；开启静音立即取消采集；解除静音不自动开始；S1 在任何状态都不能恢复设置。补充状态相关验收和本地停止的 1 秒目标。

状态：接口语义已修订；实现与故障场景待 D3/D4 验证。

### F03 · P1：共享电源初始化的位置和所有者未定义

源码依据：[app.c](../../esp32/main/app.c) 在约 2521 行初始化灯光，在约 2637 行启动语音。上游 [voice_player.c](../../esp32/main/voice_player.c) 又会在播放启停时调用 `voice_board_amp()`。

影响：仅在语音初始化时准备 GPIO8 无法保护此前的灯光访问；把播放关闭映射为 GPIO8 关闭会切断灯光和麦克风。

处理：0.2 指定单一板级模块管理 GPIO8，上电准备先于灯光初始化；首期共享电源可保持开启，播放停止通过停止数据或数字静音实现。首期录放交替使用，不承诺全双工。

状态：责任与初始化顺序已修订；稳定条件、初始化失败行为及物理状态待 D1～D4 验证。

### F04 · P1：任务验收存在前后依赖倒置

0.1 要求 D1 通过包含灯光/录音/播放组合的 S02，但这些功能到 D2/D3 才出现；D2 又要求 S06 全部通过，而 8 键路由在 D3 才开发。分区只放到 D5，也不能为前期构建提供完整布局依据。

处理：0.2 将初始分区检查放入 D1；把 S02 拆为冷启动和组合运行子项，把 S06 拆为编码器及按键业务子项，分别落到能提供相应能力的任务；D5 复核实际固件容量。

状态：依赖已修订。阶段子项结果必须分别记录，不能提前把整个 S02/S06 标记通过。

### F05 · P2：部分验收条件无法重复判断

0.1 的“无明显漏报”“无持续内存下降”“槽容量有依据”缺少操作次数、观测场景及边界；S10 的 ADC 阈值本身仍待评审。

处理：0.2 增加按键/编码器固定次数、连续语音与故障恢复轮次、音量档、取消/静音停止目标和应用槽余量评审线。ADC 阈值与网络退出时限继续作为明确未决项。

状态：部分已修订，其余参数在对应任务前确定。当前没有测试结果。

### F06 · P2：无屏电池数据需要明确输出入口

源码依据：[noise_control.cpp](../../esp32/main/noise_control.cpp) 的 `device.health` 电池数据来自受 `CONFIG_MUSE_ENABLED` 保护的 `muse_state_power()`；无屏语音构建不会因此自动产生电池读数。

处理：0.2 指定本板电池检测接入现有 `device.health`；未知数据返回 null，不为读取电池而启用全屏 UI，不输出未校准的精确百分比。

状态：输出责任已修订；ADC 测量与接口实现待 D5 验证。

## 3. 未决项与阻塞边界

| 未决项 | 需要确定的内容 | 必须在何时确定 |
| --- | --- | --- |
| 软件静音持久化 | 重启后状态、保存方式、反馈方式 | D3 业务行为实现前 |
| 灯光语义 | 绿灯含义、静音指示、状态优先级和亮度上限 | D3 业务行为实现前 |
| 回复等待与网络失败 | 超时时限、退出状态、错误提示和再次操作行为 | D4 实现前 |
| ADC 精度 | 可接受误差及测量条件 | D5 校准与验收前 |
| 硬件运行参数 | 麦克风 slot/位宽/速率、Flash 模式、供电稳定条件 | D1/D2 中取得规格或测量依据后固化 |
| 隧道默认配置 | 与语音并存的内存稳定性和必要分配要求 | D4 测量后冻结 |
| 睡眠模式及功耗 | USB 条件、KEY_WAKE 装配、唤醒行为及目标电流 | 第二阶段 D6 评审时 |

这些未决项不要求在只读评审中凭空确定。它们也不能在开发时被静默补成默认产品行为。基础驱动任务不依赖静音持久化或 TTS 服务选择，但业务任务需要满足对应边界。

## 4. 已核对的可复用点

- [components/muse/CMakeLists.txt](../../esp32/components/muse/CMakeLists.txt) 已有 `HOMEHUB_VOICE` 独立分支，无屏路径有代码依据。
- 上游麦克风 16 kHz PCM16 与扬声器 48 kHz 双声道 32 位接口可作为首期适配边界；实际器件格式仍须验证。
- 文字回复与 TTS 播放已明确区分，首期没有朗读不能作为扬声器失败证据。
- 硬件 GPIO、GPIO0 专用下载入口与 GPIO8 共享电源合同未发现文档映射冲突；这只是静态资料核对结论。
