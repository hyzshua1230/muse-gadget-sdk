# Spec：EasyInput V2 后续完善与第二阶段准入

日期：2026-10-11。状态：用户已授权按本规格推进，第2节反馈已实现，本地编译通过；等待灯效、续播及从头重播实机通过，其他边界和稳定性待验证；第二阶段扩展仍待独立评审。

## 1. 当前基线与推进顺序

现有固件支持 S1 按住说话、Qwen ASR、Muse 文字回复、Qwen TTS 分段朗读、S2 软件静音、S3 续播/重播、S4 暂停/取消、S8 配对/恢复及旋钮音量。约101秒回复的暂停续播与播完从头重播已实机确认。

建议先完成重播状态反馈与稳定性验收，再单独评审 USB HID、低功耗及离线唤醒词。后三项是独立扩展，不默认同时启用。

## 2. 重播状态反馈：下一轮最小范围

### 问题与事实

完整重播缓存使用 PSRAM，限制为4MiB（4,194,304字节），存储16kHz、PCM16、单声道音频，理论约131秒；还受实际可分配内存及64个音频段索引限制。首次朗读总长度可以超过缓存容量。

当前缓存容量超限或内存紧张会清除缓存；随后按S3只返回通用 `NO REPLAY AUDIO` 和3灯红色错误提示。该提示不能区分“尚无回复”“正在准备”“容量超限”“内存不足”或“合成失败”。容量应按转换后的缓存音频累计字节判断，不能用单个下载WAV大小或文本长度替代。

首次朗读暂停后，已有回复与合成继续完成；提前按S3会保存一次请求，完整缓存就绪后自动续播。等待期间需要可辨认的反馈。

### 本轮采用方案

缓存模块提供本轮状态与不可用原因，语音模块据此选择提示。状态随新提问和缓存生命周期更新，不能把上一轮的超限原因带入下一轮。

| 场景 | 拟定反馈 | 行为约束 |
| --- | --- | --- |
| 已暂停，按S3，完整缓存尚在准备 | 2颗暖黄色灯缓慢呼吸，表示等待续播 | 只保留一次请求；就绪后按现有规则续播 |
| 本轮容量超限或段数超限，按S3 | 5颗暖黄色灯缓慢闪烁2次，表示未保留完整重播 | 不重新调用TTS，不播放半条缓存 |
| 内存不足释放缓存，按S3 | 3颗暖黄色灯缓慢闪烁2次 | 不误报“回复过长” |
| 尚无回复或缓存已因新提问/重启清空 | 1颗暖黄色灯闪烁2次 | 不误报合成失败 |
| 合成或实际播放失败 | 沿用对应红色错误提示 | 保留失败分类，不能改成正常容量提示 |

保留现有柔和限亮与静音优先级，提示结束恢复实际状态，独立绿灯仍只表示Muse连接就绪。S1新提问、S2静音或取消清除等待续播提示及请求，解除静音不自动续播。

首轮建议只做灯光反馈。低音提示音作为可选方案，需另行确定音量、时长及是否遵守静音；不同时新增灯效与声音，不为了提示再次请求云端语音。

### 验收

1. 未提问、完整缓存、合成中、容量超限、索引超限、内存不足、合成失败分别触发S3；状态和提示对应，且日志保留具体原因。
2. 首次暂停后按S3出现等待反馈；完整缓存就绪后续播，结束后S3从头播放。
3. 等待期间反复S3、S1打断、S2静音、S4操作不会重复启动播放或让旧请求进入新会话。
4. 30轮短/长回复与断网恢复，记录成功率、时延、内部RAM/PSRAM及最大空闲块；故障后可再次提问，无持续内存下降、崩溃或看门狗。

## 3. 低功耗休眠与按键唤醒：独立评审

硬件入口为KEY_WAKE GPIO21低有效汇总信号。现有GPIO8共享LED/MIC/SPK电源，休眠前必须统一停用消费者并按板级安全顺序处理引脚。

准入条件：

- 测量当前联网空闲电流，确定USB供电/电池供电各自的休眠策略、无操作时长和功耗目标。
- 先核验GPIO21静态电平、按键汇总来源、保持按下及释放行为；不能假设旋钮旋转或按压均参与唤醒。
- 分别验证所选ESP-IDF版本下轻睡眠、深睡眠的GPIO唤醒方式及外围限制，不直接把一种配置套用于两种模式。
- 明确唤醒后联网恢复、按键首次事件处理，以及PSRAM重播缓存是否保留；深睡眠方案按重新启动设计，不承诺保留缓存。
- 录音、识别、等待回复、合成、播放或准备续播时禁止自动休眠；USB HID启用时另行评审主机交互及唤醒策略。

验收：记录实测电流、恢复联网耗时与唤醒原因；每个支持的唤醒输入重复20次，无反复立即唤醒、误恢复设置或语音任务残留。功耗与恢复时限先评审再冻结。

## 4. USB HID复合设备：独立评审

使用ESP32-S3原生USB GPIO19/20。当前板型配置采用USB Serial/JTAG控制台，同一物理USB接口接入HID前必须规划调试及烧录入口。

准入条件：

- 核验USB连接与选用USB设备栈，明确复合接口组成及Windows枚举行为；不能假设现有Serial/JTAG与HID配置可直接并存。
- 明确调试串口方案及BOOT恢复烧录流程；新增依赖或工具必须另行确认。
- 冻结语音模式与电脑控制模式的切换规则。旋钮当前调设备扬声器音量，S2当前静音麦克风；电脑音量与电脑静音不能复用后产生双重动作。
- 首轮建议媒体控制，宏按键单独确认映射、触发方式和释放规则，防止发送未要求的电脑操作。

验收：USB拔插、开机枚举、按住期间断开、模式切换、旋钮正反各20格；主机无卡键，既有语音按键与下载恢复入口仍可用。

## 5. 离线唤醒词ESP-SR：独立评审

目标是本地检测唤醒词，再进入已有云端ASR/Muse/TTS流程。离线唤醒不等于离线识别或离线问答。

用户已选择此扩展，并确认自动录音、播放期间停监听、静音停监听及内置词首版交互。实施和验收记录见[离线唤醒首版规格](easyinput-v2-offline-wake.md)；当前新增模型与源码仍待固件构建和硬件资格验证，以下资源门禁继续有效。

准入条件：

- 核验ESP-SR版本与ESP-IDF 6.0.1、ESP32-S3及模型的兼容性；明确依赖来源、模型许可与所需Flash分区。
- 测量持续采音及前端/模型运行的CPU、内部RAM和PSRAM峰值；8MiB物理PSRAM不等于模型可用余量，需与重播缓存和TLS同时预算。
- 明确唤醒后录音起止方式、最长录音、超时及误触发处理，保留S1手动入口和S2软件静音。
- 首轮优先评审播放期间暂停唤醒检测；若要求播放时可唤醒，需要单独评估参考音频、回声消除及单麦克风实测效果。
- 明确持续监听与低功耗模式如何切换；休眠期间不能承诺仍运行常规唤醒词模型。

验收：固定距离与噪声环境下记录漏检、误唤醒和响应时延；测试自身扬声器播放、连续多轮、静音及网络不可用场景。指标在选定模型后评审，不预先承诺准确率。
